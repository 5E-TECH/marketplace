# C6.7 — Admin qoldiq va Elchi integratsiyasi ko‘rinishi

Barcha endpointlar `ADMIN` va `SUPERADMIN` rollari uchun yopiq. Javoblar
standart API envelope ichida qaytadi.

## Qoldiq

```http
GET /api/v1/admin/inventory/stock
```

Filtrlar: `shopId`, `warehouseId`, `variantId`, `productId`, `search`,
`lowOnly`, `warehouseActive`, `page`, `limit`. Har qatorda `shopId`,
mahsulot/variant, ombor (`warehouseActive` bilan), `onHand`, `reserved`,
`available` va `lowStockThreshold` mavjud.

- SQL darajasida sahifalanadi. `search`/`productId` avval katalogda
  (`catalog.admin.variant-search`) variant id’lariga aylanadi; 1000 tadan
  ko‘p mos kelsa natija qisqaradi va `searchTruncated: true` bo‘ladi.
- Mahsulot nomi faqat sahifadagi qatorlar uchun, do‘kon bo‘yicha bitta RPC
  bilan olinadi. Bitta do‘kon katalogi javob bermasa endpoint yiqilmaydi:
  o‘sha do‘kon `warnings` da, qatorlari esa nomsiz qaytadi.
- Katalogda topilmagan (o‘chirilgan) variant qatori tushib qolmaydi:
  `catalogMissing: true`, nom maydonlari `null`.

```http
GET /api/v1/admin/inventory/movements
```

Filtrlar: `shopId`, `warehouseId`, `variantId`, `type`, `dateFrom`, `dateTo`,
`warehouseActive`, `page`, `limit`. Jurnal yangi yozuvdan eskisiga
tartiblanadi; qatorda mahsulot nomi/SKU va `warehouseActive` bor.

`warehouseActive` ikkala endpointda bir xil: berilmasa **barcha** omborlar
(o‘chirilganlari ham), `true` — faqat faol, `false` — faqat o‘chirilgan.

## Elchi monitoring

```http
GET /api/v1/admin/integration/shipments
```

Filtrlar: `shopId`, `status`, `shipmentId`, `shipmentState`, `dateFrom`,
`dateTo`, `page`, `limit`. Qatorda `orderStatus` (sales_order) va
`paymentMethod` ham bor.

`shipmentState`:

- `all` (sukut) — barcha seller-orderlar;
- `created` — Elchi posilkasi yaratilganlar;
- `missing` — Elchi’ga topshirilmay **qotib qolganlar**: posilka yo‘q,
  sub-buyurtma yakunlanmagan (CANCELLED/RETURNED/DELIVERED emas) va buyurtma
  tasdiqlangan yoki to‘langan (DRAFT/PENDING_PAYMENT/CANCELLED/REFUNDED emas).

```http
GET /api/v1/admin/integration/webhooks
```

Filtrlar: `eventId`, `shipmentId`, `sellerOrderId`, `status`, `dateFrom`,
`dateTo`, `page`, `limit`. Saqlangan original `payload` ham qaytadi.

## Do‘konni qayta provision qilish

```http
POST /api/v1/admin/integration/shops/:id/reprovision
```

Integration service do‘konning joriy nomi, telefoni, hududi va tariflarini
catalog service’dan oladi va Elchiga `external_seller_id` bilan idempotent
qayta yuboradi. Yangi market takroran ochilmaydi. Xatoda provisioning yozuvi
`failed` bo‘ladi va retry cron qayta urinadi. Admin amali auditga yoziladi.

Javob:

```json
{
  "shopId": "4",
  "elchiMarketId": "142",
  "status": "done",
  "reprovisioned": true,
  "error": null
}
```

## Admin paneli

- **Qoldiq** (`/admin/inventory`) — "Qoldiq" va "Harakatlar" bo‘limlari,
  do‘kon/ombor holati/kam qoldiq filtrlari.
- **Yetkazib berish** (`/admin/delivery`) — "Posilkalar" (sukut bo‘yicha
  "Topshirilmagan" ko‘rinishi ham bor) va "Webhooklar" (payload bilan).
- Do‘kon kartochkasida (`/admin/shops`) "Elchi’da qayta ro‘yxatdan o‘tkazish".
