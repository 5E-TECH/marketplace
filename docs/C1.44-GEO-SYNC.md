# C1.44 — Geo cache’ni Elchi bilan sinxron saqlash

## Ishlash tartibi

- Elchi `regions` va `districts` javobidan `sato_code` (shuningdek
  `soato_code`, `soato`, `sato` aliaslari) o‘qiladi.
- `integration.geo_cache.sato_code` ustunida SOATO/SATO kodi saqlanadi.
- Yangi hudud qo‘shiladi, o‘zgargan hudud yangilanadi, qayta paydo bo‘lgan hudud
  faollashtiriladi.
- Elchi ro‘yxatida yo‘q hudud `is_deleted=true` qilinadi.
- Elchi bo‘sh ro‘yxat qaytarsa, mavjud cache xavfsizlik uchun o‘zgartirilmaydi.
- Natija `regions`, `districts`, `added`, `updated`, `deleted` sonlari bilan
  log qilinadi.

## Avtomatik va qo‘lda sinxronlash

Kunlik cron `Asia/Tashkent` vaqti bilan 02:00 da ishlaydi.

Admin qo‘lda ishga tushirishi mumkin:

```http
POST /api/v1/admin/integration/geo/sync
Authorization: Bearer <ADMIN_OR_SUPERADMIN_TOKEN>
```

Javob misoli:

```json
{
  "regions": 14,
  "districts": 181,
  "added": 1,
  "updated": 2,
  "deleted": 1
}
```

Public ro‘yxat endpointlari:

```http
GET /api/v1/regions
GET /api/v1/regions/:regionId/districts
```

Har bir element `satoCode` maydonini qaytaradi.
